# Local GitHub Actions Runner

## Purpose

Use this runbook to operate a repository-scoped GitHub Actions runner on a
trusted personal macOS ARM64 workstation for the PR Attention Router proof of
concept.

The runner executes workflow code as the local macOS user. Attach it only to a
private repository containing trusted pull requests. Run it interactively and
remove its repository registration when the POC is inactive.

## Runner identity

| Repository | Runner name | Installation directory |
| --- | --- | --- |
| `jdavault/risk-based-pr-attention-routing` | `Joes-MacBook-Pro-2` | `/tmp/risk-router-runner-arm64` |

The workflows select the default labels assigned by GitHub:

```yaml
runs-on: [self-hosted, macOS, ARM64]
```

## Prerequisites

- Repository administrator access.
- A private repository on `github.com`.
- A macOS ARM64 workstation with outbound HTTPS access to GitHub.
- Trusted, same-repository pull requests authored by `jdavault`.
- No repository secrets are required for the runner smoke test.

Do not attach this workstation runner to a public repository or to a repository
that accepts untrusted pull requests. A pull-request workflow can execute code
on the runner as the local macOS user.

## Download and verify

1. Open the repository on GitHub.
2. Go to **Settings → Actions → Runners → New self-hosted runner**.
3. Select **macOS** and **ARM64**.
4. Create and enter the installation directory:

   ```bash
   mkdir -p /tmp/risk-router-runner-arm64
   cd /tmp/risk-router-runner-arm64
   ```

5. Run the download command shown by GitHub for the current ARM64 runner.
6. Run the checksum command shown by GitHub. Continue only when it succeeds.
7. Run the extraction command shown by GitHub.

Use only the commands generated by the repository's runner setup page. Runner
versions and short-lived registration tokens change over time. Never paste a
registration token into chat, source control, shell history, or documentation.

## Configure

Use the short-lived token from the setup page to register a repository-scoped
runner:

```bash
./config.sh \
  --url https://github.com/jdavault/risk-based-pr-attention-routing \
  --token <registration-token> \
  --name Joes-MacBook-Pro-2 \
  --work _work \
  --unattended
```

The runner receives the `self-hosted`, `macOS`, and `ARM64` labels
automatically. Do not add `--ephemeral` or `--once` for this interactive POC
runner; instead, remove its registration during the teardown procedure below.

## Start

Start the runner without corporate proxy or GitHub Enterprise overrides:

```bash
cd /tmp/risk-router-runner-arm64
./run.sh
```

Keep the terminal open. The runner is ready when it reports `Listening for
Jobs` and GitHub shows it as **Idle** under **Settings → Actions → Runners**.

## Verify with the smoke test

The workflow `.github/workflows/runner-smoke-test.yml` has no application,
Node.js, OpenAI, or notification dependency.

1. Open **Actions → Local runner smoke test**.
2. Select **Run workflow** on the branch containing the workflow.
3. Confirm that **Verify local macOS runner** succeeds.

The smoke test proves that GitHub can route a job to the workstation and that
the runner can check out this repository without retaining Git credentials.

You can also watch the run locally:

```bash
gh run watch <run-id> --interval 5 --exit-status
```

## Application workflow gate

The validation and PR attention workflows remain disabled while the app is
being reconstructed. Their jobs require this repository variable:

```text
PAR_APP_WORKFLOWS_ENABLED=true
```

Leave the variable absent or set it to `false` until all files under
`apps/attention-router` are committed and the following commands pass locally:

```bash
npm ci --prefix apps/attention-router
npm run lint --prefix apps/attention-router
npm run typecheck --prefix apps/attention-router
npm test --prefix apps/attention-router
npm run build --prefix apps/attention-router
```

After those checks pass, add the variable under **Settings → Secrets and
variables → Actions → Variables**, open a pull request, and confirm that
**Validate repository** succeeds before configuring provider credentials.

## Provider configuration for the later classification test

The smoke test does not require secrets. Configure these only after validation
passes and immediately before testing the complete attention workflow:

| Kind | Name | Purpose |
| --- | --- | --- |
| Secret | `OPENAI_API_KEY` | Codex classification through the action's credential proxy. |
| Variable | `PAR_EMAIL_ENABLED` | Set to `true` only for an intentional delivery test. |
| Variable | `SMTP_HOST` | SMTP host reachable from the runner; `localhost` for local smtp4dev. |
| Variable | `SMTP_PORT` | SMTP port; `25` for the POC and work-aligned setup. |
| Variable | `PAR_EMAIL_FROM` | Email sender address. |
| Variable | `PAR_EMAIL_TO_TEAM` | Comma-delimited LOW and MEDIUM recipients. |
| Variable | `PAR_EMAIL_TO_LEAD` | Comma-delimited HIGH recipients. |
| Secret | `SLACK_BOT_TOKEN` | Bot user OAuth token used only by the Slack notification job. |
| Variable | `PAR_SLACK_CHANNEL_ID` | Slack channel ID containing the bot. |
| Variable | `PAR_SLACK_ENABLED` | Set to `true` only for an intentional Slack delivery test. |

Keep `PAR_EMAIL_ENABLED` absent or `false` until the SMTP adapter has automated
tests and one intentional local delivery succeeds. Never commit recipient
addresses or registration tokens.

## Codex boundary

The classification job uses the reviewed Codex Action release tag aligned
with the master workflow and
`safety-strategy: read-only`. Codex may inspect the checked-out pull request but
cannot write to the filesystem or access the network directly. The action
proxies the API request using `OPENAI_API_KEY`.

Keep the existing safeguards:

- successful and failed validation runs can trigger classification so a failed
  validation establishes its deterministic floor;
- only `jdavault`-authored, same-repository pull requests are accepted;
- the pull request head SHA must still match the validated SHA;
- the Codex job has `contents: read` permission only;
- the PR source is never modified;
- persistent comment publication happens in a separate least-privilege job.

This is a persistent self-hosted runner. A process started by validated code
could survive into a later job. For the POC, use only this private synthetic
repository, accept only your own pull requests, keep real company source off the
runner, use project-specific provider credentials, and tear the runner down
after each active testing session.

## Teardown

1. Confirm the runner is not busy under **Settings → Actions → Runners**.
2. Stop `run.sh` with `Ctrl+C`.
3. Remove the runner from the repository's runner settings. Alternatively,
   generate a fresh removal token and run `./config.sh remove` locally.
4. Confirm that GitHub no longer lists the runner.
5. Move `/tmp/risk-router-runner-arm64/_work` to Trash.

The downloaded runner archive and installation files may be retained, but
check the repository setup page for a required runner update before registering
it again.

## Troubleshooting

| Symptom | Response |
| --- | --- |
| `Not configured. Run config.sh` | Register the runner with a fresh token from the repository setup page. |
| Runner is offline | Start `./run.sh` and wait for `Listening for Jobs`. |
| Job remains queued | Confirm the runner is idle and has `self-hosted`, `macOS`, and `ARM64` labels. |
| Smoke test cannot check out the repository | Confirm the runner is registered to this repository and can reach `github.com` over HTTPS. |
| Runner registration token is rejected | Generate a new token; registration tokens expire quickly. |
| Application jobs are skipped | Keep them skipped while the app is incomplete; later set `PAR_APP_WORKFLOWS_ENABLED=true`. |
| Codex job cannot authenticate | Confirm `OPENAI_API_KEY` exists as a repository Actions secret and was not stored as a variable. |
| Email job is skipped | This is expected until `PAR_EMAIL_ENABLED=true`. |
| Slack job is skipped | This is expected until `PAR_SLACK_ENABLED=true`. |

GitHub's current runner installation commands and token are authoritative when
they differ from this runbook.
